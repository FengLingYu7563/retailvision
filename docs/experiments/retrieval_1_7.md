# 實驗紀錄：驗收 1.7 以圖搜圖（標準圖 gallery）

日期：2026-10-14　模型：cls-mnv3-v1（MobileNetV3-Large 雙頭，neck 1280 維 embedding）

## 結論

**未達標**。門檻為 test top-1 >= 70%，最終結果 54.5%（top-5 83.4%）。
依規格第 9 節規則，不降低門檻，在此記錄原因與嘗試過程。

## 嘗試（全部只在 val 296 張上比較，test 只在最後跑一次）

| # | 做法 | val top-1 | val top-5 |
|---|---|---|---|
| 1 | 標準圖 + 水平翻轉 | 53.0% | 87.5% |
| 2 | 再加 2x2、3x3 排列（模擬一整堆） | **55.4%** | 91.2% |
| 2b | 再加中央放大裁切 | 56.1% | 89.5% |
| 3 | 改用 backbone 960 維 pooled 特徵（配合 #2） | 42.9% | 79.4% |
| 3b | 960 + 1280 串接 | 52.0% | 89.9% |
| 4 | 白底摳圖後貼到模糊賣場背景 / 深色背景 | 51.4% 到 52.7% | 86.5% 到 87.2% |

#4 沒有比 #2 進步，觸發「沒有進步」的停止條件，停止調整。
最後採用 #2（#2b 的 top-1 只多 0.7 個百分點、top-5 反而下降，val 只有 296 張，這個差距在雜訊範圍內，所以選比較簡單的 #2）。

test 結果（#2）：top-1 54.5%、top-5 83.4%。

## 原因分析

1. **Domain gap**：標準圖是單一商品、白底、棚拍光線；測試圖是店內實拍，一整堆商品、裝在塑膠袋裡、有價格牌和其他商品入鏡（見 Grocery Store 論文 Fig. 1）。
2. **每類只有 1 張參考圖**：沒有角度與外觀上的變化可以涵蓋。
3. embedding 是用分類損失訓練的，只看過店內實拍照，從沒看過白底圖。

## 對照：實際的新品登錄情境

規格的新品登錄流程（`POST /catalog/products`）是上傳 1 到 5 張**實拍**參考圖。
用每類 3 張訓練集實拍照當 gallery：test top-1 **79.7%**、top-5 **97.0%**，代表 embedding 本身可以用，瓶頸是參考圖的來源。

## 可能的改進方向（未實作）

- 訓練時加入度量學習損失（例如 ArcFace / SupCon），讓 embedding 不只為分類服務。
- 把白底圖用摳圖貼背景的方式加入訓練資料（會讓 gallery 圖在訓練時被看過，評估上要另外設計，避免資料洩漏）。
- 改用自監督預訓練的 backbone（例如 DINOv2），對 domain gap 比較穩健，但 CPU 延遲會增加。
